# Fix apps/demo tsconfig.json Errors

## Root Cause

1. **"File 'next/tsconfig.json' not found"**: TypeScript resolves `extends: "next/tsconfig.json"` via Node module resolution from the tsconfig location. In a monorepo with npm workspaces, module resolution can fail when:
  - The IDE/TypeScript server runs from the repo root
  - `node_modules` is not yet installed or Next.js is hoisted differently than expected
2. **"Cannot use JSX unless the '--jsx' flag is provided"**: When the `extends` fails, the config effectively becomes empty (or partially applied), so the `jsx` compiler option is missing.

## Solution

Use a **standalone tsconfig** instead of extending Next.js. Next.js 14's create-next-app template for TypeScript uses a standalone config (no `extends`) that works reliably in all environments.

## Implementation

Replace the contents of [apps/demo/tsconfig.json](apps/demo/tsconfig.json) with this standalone Next.js 14-style config:

```json
{
  "compilerOptions": {
    "target": "es5",
    "lib": ["dom", "dom.iterable", "esnext"],
    "allowJs": true,
    "skipLibCheck": true,
    "strict": true,
    "noEmit": true,
    "esModuleInterop": true,
    "module": "esnext",
    "moduleResolution": "bundler",
    "resolveJsonModule": true,
    "isolatedModules": true,
    "jsx": "preserve",
    "incremental": true,
    "baseUrl": ".",
    "paths": {
      "@/*": ["./src/*"]
    }
  },
  "include": ["next-env.d.ts", "**/*.ts", "**/*.tsx"],
  "exclude": ["node_modules"]
}
```

Key points:

- `**"jsx": "preserve"**` — Enables JSX (fixes the second error)
- **No `extends`** — Avoids resolution of `next/tsconfig.json` (fixes the first error)
- `**paths` and `baseUrl**` — Preserve existing `@/*` alias to `./src/*`
- `**include**` — Standard Next.js pattern; `next-env.d.ts` is auto-generated by Next.js on first `next dev`/`next build`

## Verification

1. Run `npm install` from the repo root (ensure dependencies exist)
2. Run `npx tsc --noEmit -p apps/demo/tsconfig.json` — should complete with no errors
3. Run `cd apps/demo && npm run build` — Next.js build should succeed
4. Open a `.tsx` file in the IDE — JSX and path aliases should resolve correctly

## Note on next-env.d.ts

Next.js generates `next-env.d.ts` when you run `next dev` or `next build`. If the file does not exist yet, TypeScript may warn. Running `next dev` once will create it. Alternatively, you can add a minimal `next-env.d.ts` with `/// <reference types="next" />` and `/// <reference types="next/image-types/global" />` if needed before the first run.
